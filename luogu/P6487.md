## 题目简述

有 $n$ 枚石子。两位玩家定了如下规则进行游戏：

- Mirko 先取一次，Slavko 再取一次，然后 Mirko 再取一次，两人轮流取石子，以此类推；
- Mirko 在第一次取石子时可以取走任意多个；
- 接下来，每次至少要取走一个石子，最多取走上一次取的数量的 $2$ 倍。当然，玩家取走的数量必须不大于目前场上剩余的石子数量。
- 取走最后一块石子的玩家获胜。

双方都以最优策略取石子。Mirko 想知道，自己第一次至少要取走几颗石子最终才能够获胜。

输入格式
输入一行一个整数 $n$，表示石子的数量。

输出格式
输出一行一个整数，表示 Mirko 最少取多少石子可以保证获胜。

说明/提示
#### 样例 1 解释

对于这个样例，Mirko 第一次可以取 $1/2/3/4$ 个。虽然他取 $4$ 个会直接赢得比赛，但这并不是最少的。最少的方案是取走 $1$ 个。这样 Slavko 只能取走 $1$ 个或者 $2$ 个。无论选择哪种，Mirko 下一步都能取走所有的石子并获胜。

#### 数据规模与约定

对于 $100\%$ 的数据，保证 $2\le n\le 10^{15}$。

## 解题思路

这是经典的“斐波那契取石子”博弈（Zeckendorf 博弈）。

- 关键观察：若当前石子数 n 是斐波那契数，则先手第一次必须取走全部 n 枚才能获胜（否则后手可把局面重新变成斐波那契数并保持优势）。因此答案为 n。
- 若 n 不是斐波那契数，利用 Zeckendorf 定理把 n 拆成若干个互不相邻的斐波那契数之和。从大到小贪心减去斐波那契数，最后减去的那个斐波那契数就是最少首取数量。
- 代码先预处理出不超过 10^18 的斐波那契数列（从 1,2 开始），然后对 n 做判断：若 n 在数列中直接返回 n；否则从大到小扫描，不断用 n 减去当前斐波那契数，并记录最后一次减去的数作为答案。
- 正确性要点：Zeckendorf 表示唯一，且贪心得到的最后一个斐波那契数正是先手保持必胜所需的最小首取量；该结论与“每次最多取上次 2 倍”的规则相匹配。

## 复杂度分析

- 时间复杂度：O(log n)（斐波那契数列长度约为 log_φ n，扫描一次）
- 空间复杂度：O(log n)（存储斐波那契数列）

## 代码

```text
#include<bits/stdc++.h>
using namespace std;
typedef long long ll;
vector<ll> fib;
void pre(){
    fib.push_back(1);
    fib.push_back(2);
    while(true){
        ll nxt=fib.back()+fib[fib.size()-2];
        if(nxt>1e18){
            break;
        }
        fib.push_back(nxt);
    }
}

ll solve(ll n){
    for(auto x:fib){
        if(x==n){
            return n;
        }
    }
    ll res=1e18;
    ll tmp=n;
    for(int i=fib.size()-1;i>=0;i--){
        if(tmp>=fib[i]){
            tmp-=fib[i];
            res=fib[i];
        }
    }
    return res;
}

int main(){
    pre();
    ll n;
    cin>>n;
    cout<<solve(n);
    return 0;
}
```

## 复盘备注

易错点：
- 斐波那契数列应从 1,2 开始（而非 1,1），否则会破坏 Zeckendorf 表示的唯一性。
- n 本身是斐波那契数时答案就是 n，不能继续拆分。
- 贪心时需从大到小扫描，并记录最后一次减去的斐波那契数。

可优化点：预处理上界可设为 10^15 稍大即可，当前 10^18 也安全。
