## 题目简述

偏远的小镇上，三兄弟共同经营着一家小型矿业公司“兄弟矿业”。公司旗下有三座矿山：金矿、银矿和铜矿，它们的初始产值分别用非负整数 $A$、$B$ 和 $C$ 表示。这些矿山的产出是小镇经济的核心，支撑着三兄弟和许多矿工家庭的生计。

然而，各矿山的产值波动剧烈，有时金矿收益高而银矿、铜矿低迷，有时则相反。这种不稳定性让公司收入难以预测，也常引发兄弟间的争执。为了稳定经营，三兄弟设计了一个公平的产值调整策略，每年执行一次，每次调整时，将根据当前的产值 $A$、$B$、$C$，计算新产值：

1. 金矿新产值：$A'=\lfloor \dfrac{B+C}{2} \rfloor$；
2. 银矿新产值：$B'=\lfloor \dfrac{A+C}{2} \rfloor$；
3. 铜矿新产值：$C'=\lfloor \dfrac{A+B}{2} \rfloor$；

其中，$\lfloor \rfloor$ 表示向下取整。例如，$\lfloor 3.7\rfloor = 3$，$\lfloor 5.2\rfloor = 5$。

计算出 $A'$、$B'$、$C'$ 后，同时更新：$A$ 变为 $A'$，$B$ 变为 $B'$，$C$ 变为 $C'$，作为下一年调整的基础。

三兄弟认为这个方法能平衡产值波动，于是计划连续执行 $K$ 次调整。现在，请你帮他们计算，经过 $K$ 次调整后，金矿、银矿和铜矿的产值分别是多少。

输入格式
输入的第一行包含一个整数 $T$，表示测试用例的数量。

接下来的 $T$ 行，每行包含四个整数 $A,B,C,K$，分别表示金矿、银矿和铜矿的初始产值，以及需要执行的调整次数。

输出格式
对于每个测试用例，输出一行，包含三个整数，表示经过 $K$ 次调整后金矿、银矿和铜矿的产值，用空格分隔。

说明/提示
### 评测用例规模与约定

- 对于 $30\%$ 的评测用例，$1 \leq T \leq 100$，$1 \leq A, B, C, K \leq 10^5$。
- 对于 $100\%$ 的评测用例，$1 \leq T \leq 10^5$，$1 \leq A, B, C, K \leq 10^9$。

## 解题思路

关键观察：三个数在若干次调整后会迅速趋于相等，一旦 A=B=C 则后续不再变化，可以提前结束。

算法选择：直接模拟每次调整，但在循环中检测 A==B==C 时 break。由于每次调整后最大值与最小值的差距大约减半，最多约 O(log(max(A,B,C))) 次就会收敛到三数相等，因此即使 K 高达 1e9，实际循环次数也很少。

正确性要点：
1. 更新时必须用旧的 A、B、C 同时计算新值，代码中先用 na、nb、nc 保存新值再统一赋值，符合题意。
2. 当 A=B=C 时，代入公式仍有 A'=B'=C'=A，状态不变，提前退出不影响结果。
3. 使用 long long 防止中间计算溢出（虽然本题数值范围下 int 也够，但更安全）。

## 复杂度分析

- 时间复杂度：O(T log M)，其中 M=max(A,B,C)，因为每次迭代三数极差大致减半，收敛很快；最坏每组约 O(log M) 次。
- 空间复杂度：O(1)，仅使用常数个变量。

## 代码

```text
#include<bits/stdc++.h>
#define int long long
using namespace std;

signed main() {
    int t;
    cin >> t;
    while (t--) {
        int a, b, c, k;
        cin >> a >> b >> c >> k;

       
        for (int i = 1; i <= k; i++) {
            if(a==b&&b==c) break;
            int na = (b + c) / 2;
            int nb = (a + c) / 2;
            int nc = (a + b) / 2;
            a = na;
            b = nb;
            c = nc;
        }

        cout << a << " " << b << " " << c << "\n";
    }
    return 0;
}
```

## 复盘备注

易错点：
- 必须同时更新，不能先改 A 再用新 A 算 B、C。
- 虽然 K 很大，但不要直接循环 K 次，否则会超时；利用收敛性提前 break。
- 注意使用 long long 避免潜在溢出。

可优化点：本题模拟已足够快，无需进一步优化。

同类题提示：遇到“多次迭代后趋于稳定”的题目，可先分析收敛速度或寻找不动点，再决定是否直接模拟。
